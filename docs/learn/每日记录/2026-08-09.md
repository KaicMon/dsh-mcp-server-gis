## 第一课：先建立项目地图

这个项目不是单一的 MCP Server，而是由三部分组成：

1. `mcp_server`：接收 MCP/JSON-RPC 请求，将请求分发给插件。
2. `mcp_client`：连接服务端、发现工具并调用工具。
3. `mcp_client/src/rag`：根据用户问题检索相关工具，减少交给大模型的工具数量。

可以先把系统记成下面这条主线：

```text
用户问题
  → AI Agent
  → MCPAgentIntegration
  → MCPClient
  → JSON-RPC / Transport
  → MCP Server
  → Plugin
  → 执行结果原路返回
```

RAG-MCP 位于 Agent 调用工具之前：

```text
用户问题
  → Embedding
  → VectorIndex 检索 Top-K 工具
  → 把候选工具交给大模型
  → 大模型决定是否调用工具
```

## 第一条需要掌握的调用链

以调用 `calculator` 为例：

1. Client 构造 `tools/call` JSON-RPC 请求。
2. Transport 将请求送入 Server。
3. `Server` 根据方法名选择 `tools/call` 回调。
4. `main.cpp` 注册的回调遍历已加载插件及其工具。
5. 找到名为 `calculator` 的工具后调用插件的 `HandleRequest()`。
6. Calculator 插件读取 `params.arguments.expression`。
7. 插件计算结果并返回包含 `content` 和 `isError` 的 JSON。
8. Server 将插件结果放入 JSON-RPC 响应并返回 Client。

## 疑问与临时记录

> 学习过程中可直接把问题、猜测和实验结果追加到这里；学习结束后再统一整理。

- 问题：Client 的主函数在哪里，请求由谁发起？
  - `mcp_client` 是静态库，本身没有固定的 `main()`。
  - 宿主程序负责创建 `MCPClient` 或 `MCPAgentIntegration`，并通过 `listTools()`、`callTool()` 等公开方法发起请求。
  - 项目中的宿主示例可参考 `examples/rag_mcp_example.cpp`。
- 问题：Plugin 和 Tool 是什么组织关系？
  - 一个 Plugin 可以包含多个 Tool；`GetToolCount()` 和 `GetTool(index)` 用于枚举插件提供的工具。
  - Server 先根据 `params.name` 找到拥有目标 Tool 的 Plugin，再把完整请求交给该插件的 `HandleRequest()`。
  - 插件内部再次读取 `request["params"]["name"]`，据此分发到具体工具实现。
- JSON-RPC 与初始化检查题：
  - 缺少 `method` 属于 JSON-RPC 请求错误。
  - `no_tool` 在当前实现中由有效的 `tools/call` 方法处理，并以 `result.isError=true` 返回，属于 MCP Tool 层错误。
  - 除数为零属于 Tool 执行错误，同样使用 `result.isError=true`。
  - Notification 没有 `id`，不需要普通响应。
  - 两个并发请求使用相同 ID 时，Client 无法可靠关联请求和响应；当前 Client 使用秒级时间戳生成 ID，存在碰撞风险。
- Server 主循环检查题：
  - Server 只依赖 `ITransport::Read/Write`，不知道底层是 STDIO 还是 SSE。
  - JSON 成功解析后 `parserErrors_` 会清零，因此两组各 30 次、被一次成功解析隔开的错误不会触发 50 次连续错误上限。
  - 普通响应和异步通知共用输出锁，防止两个 JSON 字符串交错写入。
  - 分发边界修正：`Server::HandleRequest()` 按 `method` 找处理函数；`tools/call` 回调按工具名找插件；插件再按工具名执行内部实现。
- 工具发现与调用检查：
  - `tools/list`：由 `main.cpp` 覆盖默认回调，汇总所有 Tools 类型插件所声明的工具元数据。
  - `tools/call`：根据 `params.name` 找到声明目标工具的插件，调用其统一 `HandleRequest()`，由插件内部完成具体工具分发。
  - 尚需特别记住：插件返回 `isError=true` 后，当前 `main.cpp` 会无条件覆盖为 `false`，导致工具错误状态被掩盖。
