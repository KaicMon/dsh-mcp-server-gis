## 实验结果

- WSL CMake：3.22.1，满足项目要求的 3.20+。
- WSL C++ 编译器：GCC 11.4.0，支持项目所需 C++20。
- 构建程序：`/usr/bin/make`；未发现 Ninja。
- `jsoncpp`：1.9.5。
- `libcurl`：7.81.0。
- 已存在 `build/`，尚不存在 `build-local/`。
- 一次初始检查误用了宿主 PowerShell 下的 Windows/MSYS2 工具；随后通过显式进入 WSL 得到上述有效结果。
- 用户执行 `cmake -S . -B build-local -DCMAKE_BUILD_TYPE=Debug`，配置成功且未报告问题。
- 用户执行 `cmake --build build-local -j"$(nproc)"`，全部默认目标编译、链接成功。
- 产物检查确认生成 `mcp_server`、`libmcp_client.a`、`rag_mcp_example` 和六个插件 `.so`。
- `file` 确认 Server 是 x86-64 Linux ELF PIE，动态链接，包含调试信息且未剥离符号。
- 插件位于 `build-local/mcp_server/plugins/*/*.so`；`PluginsLoader::LoadPlugins()` 使用 `recursive_directory_iterator`，可从上级 plugins 目录递归发现。
- STDIO `initialize` 实测成功：响应保持请求 ID `init-1`，协议版本为 `2024-11-05`，Server 为 `mcp-server` 0.7.0，并声明 logging、prompts、resources 和 tools 能力。

- `tools/list` 返回 12 个工具：`sleep`、`progress_test`、`logging_test`、`get_weather`，以及 calculator 插件的 `calculator/add/subtract/multiply/divide/power/sqrt/factorial`。
